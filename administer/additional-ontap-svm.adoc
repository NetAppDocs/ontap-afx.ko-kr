= AFX 스토리지 시스템 SVM에 대한 추가 관리
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
일반적인 AFX SVM 관리 외에도 환경에 따라 수행해야 할 추가 작업이 있을 수 있습니다. 대부분의 추가 작업은 System Manager를 사용하여 수행할 수 있지만, 경우에 따라 CLI를 사용해야 할 수도 있습니다. 설명된 ONTAP 기능 및 관리는 AFX 스토리지 시스템과 Unified ONTAP를 실행하는 AFF 또는 FAS 시스템에 공통적으로 적용됩니다. 관련 Unified ONTAP 문서 링크는 필요에 따라 포함되어 있습니다.


TIP: 추가 ONTAP AFX 기능 및 구성에 대한 간략한 설명을 검토하십시오. 원하는 옵션을 찾지 못한 경우 하단의 링크를 통해 추가 자료를 확인하십시오.



[[storage-management-and-performance]]
== 스토리지 관리 및 성능

AFX 배포와 함께 구성하고 사용할 수 있는 몇 가지 선택적 스토리지 관리 및 성능 기능이 있습니다.



[[ontap-nas-storage-management]]
=== ONTAP NAS 스토리지 관리

NAS(네트워크 연결 스토리지)는 네트워크상의 여러 클라이언트가 액세스할 수 있는 전용 파일 스토리지를 제공합니다. ONTAP는 여러 NAS 프로토콜을 지원합니다. 자세한 내용은 다음을 참조하십시오 https://docs.netapp.com/us-en/ontap/nas-management/index.html["NAS 스토리지 관리"^].



[[ontap-flexcache-volumes]]
=== ONTAP FlexCache 볼륨

FlexCache는 ONTAP 원격 캐싱 기능입니다. 데이터를 클라이언트에 더 가깝게 배치하여 액세스 성능을 향상시키고 비용을 절감합니다. FlexCache 볼륨을 생성하면 처음에는 원본 파일 시스템에서 메타데이터만 복사하므로 파일 배포가 간소화되고 WAN 트래픽이 줄어듭니다. 자세한 내용은 다음을 참조하십시오 https://docs.netapp.com/us-en/ontap/flexcache/index.html["ONTAP FlexCache 볼륨"^].



[[ontap-flexgroup-volumes]]
=== ONTAP FlexGroup 볼륨

FlexGroup 볼륨은 트래픽을 자동으로 투명하게 공유하는 여러 멤버 볼륨으로 구성됩니다. FlexGroup 볼륨은 고성능 및 간소화된 관리를 비롯한 여러 이점을 제공합니다. 자세한 내용은 다음을 참조하십시오 https://docs.netapp.com/us-en/ontap/flexgroup/creation-workflow-task.html["FlexGroup 볼륨 설정"^].



[[cross-file-sequential-read]]
=== 교차 파일 순차 읽기

CFSR(Cross File Sequential Read)은 ONTAP 9.19.1 이상 버전의 AFX 시스템에서 사용할 수 있는 기능으로, 비디오 편집 및 관련 애플리케이션의 성능을 향상시켜 줍니다. 비디오 프레임을 개별 순차 파일(일반적으로 각 파일 크기는 50~250MB)로 저장하는 워크플로의 경우, CFSR은 순차적인 파일 이름 패턴을 기반으로 다음 파일을 지능적으로 예측하고 미리 가져옵니다. 최대 10개의 파일 또는 500MB의 데이터를 미리 가져올 수 있어 읽기 지연 시간을 크게 줄이고 4K/8K raw 비디오를 초당 30프레임으로 부드럽게 재생할 수 있습니다.

CFSR은 ONTAP 9.19.1 이상 버전을 실행하는 AFX 시스템에서 기본적으로 활성화되어 있지만, 개별 볼륨에서 명시적으로 활성화해야 합니다. 스토리지 관리자는 ONTAP CLI 또는 해당 REST API 호출을 사용하여 이 기능을 구성할 수 있습니다. CLI를 사용하면 새 볼륨을 생성하는 과정에서 CFSR을 활성화할 수 있습니다. 또한 다음 명령을 사용하여 기존 볼륨을 업데이트할 수도 있습니다.

`volume modify -volume <volume_name> -aggressive-readahead-mode [cross_file_sequential_read|none]`

.예
[source, bash]
----
volume modify -volume myvolume -aggressive-readahead-mode cross_file_sequential_read
volume show -volume myvolume -fields aggressive-readahead-mode
----
CFSR 기능은 FlexVol 및 FlexGroup 볼륨 모두와 호환되며 파일 확장자에 관계없이 십진수 및 16진수 파일 이름 번호 지정 체계를 지원합니다. NFSv4.x 프로토콜의 경우 CFSR은 MPIO(Multi-Protocol I/O) 읽기 기능과 통합되어 후속 읽기를 메모리에서 직접 처리함으로써 성능을 더욱 향상시킵니다. CFSR은 AFX 시스템에서만 사용할 수 있으며 지원되는 볼륨에 제한이 있습니다. 다음 볼륨 유형에서는 지원되지 않습니다:

* FabricPool 지원 볼륨
* FlexCache 엔드포인트 볼륨
* SnapMirror 타겟 볼륨


CFSR은 다른 ONTAP 플랫폼(FAS, AFF 또는 ASA)이나 Cloud Volumes ONTAP과 같은 클라우드 배포에서는 지원되지 않습니다. GDD를 활성화 또는 비활성화한 상태로 FlexGroup 볼륨을 사용하여 작동할 수 있습니다. 그러나 비디오 프레임 파일은 일반적으로 GDD의 최소 세그먼트 크기보다 훨씬 작기 때문에 GDD는 이러한 파일을 FlexGroup 구성 요소 전체에 효율적으로 스트라이프하지 못합니다. 즉, GDD는 CFSR의 파일 사전 가져오기 동작에 직접적인 영향을 거의 미치지 않습니다.



[[data-protection]]
== 데이터 보호

AFX 배포와 함께 구성하고 사용할 수 있는 선택적 데이터 보호 기능이 여러 가지 있습니다.



[[consistency-groups]]
=== 일관성 그룹

일관성 그룹은 단일 단위로 관리되는 볼륨 모음입니다. 자세한 내용은 다음을 참조하세요 https://docs.netapp.com/us-en/ontap/consistency-groups/index.html["ONTAP 일관성 그룹"^].



[[snaplock]]
=== SnapLock

볼륨 수준에서 파일을 WORM(쓰기 한 번, 읽기 여러 번) 상태로 변환하여 파일을 보호할 수 있습니다. SnapLock은 두 가지 모드를 지원합니다. 규정 준수 모드는 보존 기간이 만료될 때까지 파일을 삭제할 수 없도록 하여 정부 또는 업계별 규정을 준수합니다. 엔터프라이즈 모드는 권한이 있는 사용자가 보존 기간이 만료되기 전에 파일을 삭제할 수 있도록 합니다. 자세한 내용은 다음을 참조하세요 https://docs.netapp.com/us-en/ontap/snaplock/index.html["ONTAP SnapLock"^].



[[snapmirror-active-sync-for-nas]]
=== SnapMirror NAS용 활성 동기화

SnapMirror 액티브 싱크는 사이트 전체 장애 발생 시에도 비즈니스 서비스가 중단 없이 계속 작동하도록 지원합니다. 이 기술을 통해 애플리케이션은 수동 개입이나 사용자 지정 스크립트 없이도 보조 복사본으로 원활하게 페일오버될 수 있습니다. 자세한 내용은 https://docs.netapp.com/us-en/ontap/snapmirror-active-sync/protect-nas-task.html["SnapMirror NAS용 활성 동기화"^]을 참조하십시오.



[[storage-efficiency]]
== 스토리지 효율성

ONTAP는 스토리지 사용량을 최적화하고 비용을 절감하는 데 도움이 되는 여러 스토리지 효율성 기능을 제공합니다.



[[global-deduplication]]
=== 전역 중복 제거

https://docs.netapp.com/us-en/ontap/concepts/deduplication-concept.html["중복제거"^]은 https://docs.netapp.com/us-en/ontap/volumes/deduplication-data-compression-efficiency-concept.html["ONTAP 스토리지 효율성"^] 기능으로 중복 데이터 블록을 식별하고 제거하여 물리적 스토리지 요구 사항을 줄여줍니다. 기존의 중복제거는 볼륨 또는 애그리게이트 수준에서 작동합니다. 이러한 기존 기능은 모든 ONTAP 플랫폼에서 고객에게 상당한 스토리지 효율성을 제공합니다.

ONTAP 9.19.1부터 AFX는 스토리지 가용성 영역(SAZ) 전체로 중복 제거 기능을 확장하여 새로운 운영 범위를 제공합니다. 전역 중복 제거는 볼륨 수준 중복 제거를 기반으로 SAZ 전체 볼륨에서 중복 블록을 자동으로 제거합니다. 전역 중복 제거 세션은 자동으로 트리거되므로 수동 개입 없이 최적의 절감 효과를 얻을 수 있습니다.

AFX A1K 시스템에서는 전역 중복 제거 기능이 기본적으로 활성화되어 있으며, 최소한의 성능 영향으로 백그라운드에서 투명하게 작동합니다. 별도의 기능 라이선스가 필요하지 않으며, 압축 및 컴팩션을 포함한 기존 스토리지 효율성 기술과 원활하게 통합됩니다. 전역 중복 제거를 통해 절감되는 용량은 스토리지 효율성 지표를 통해 확인할 수 있습니다. 이 기능은 데이터가 여러 볼륨에 걸쳐 자주 공유되거나 복제되는 애플리케이션 워크로드에 특히 유용합니다.



[[security]]
== 보안

AFX 배포 시 구성하고 사용할 수 있는 선택적 보안 기능이 여러 가지 있습니다.



[[fpolicy]]
=== 정책

FPolicy는 스토리지 가상 머신(SVM)에서 파일 액세스 이벤트를 모니터링하고 관리하는 데 사용되는 파일 액세스 알림 프레임워크입니다. FPolicy를 사용하면 사용자가 정의한 기준에 따라 모니터링하고 선택적으로 차단할 파일 작업을 정의하는 정책을 생성할 수 있습니다. FPolicy는 일반적으로 보안 감사, 규정 준수 및 데이터 거버넌스에 사용됩니다. 자세한 내용은 https://docs.netapp.com/us-en/ontap/nas-audit/two-parts-fpolicy-solution-concept.html["ONTAP FPolicy 솔루션"^]을 참조하십시오.



[[nfs-over-tls]]
=== TLS를 통한 NFS

ONTAP 9.19.1부터 ONTAP NFS가 활성화된 SVM에서 전송 중인 NFS 트래픽을 암호화하기 위해 TLS 1.3을 사용하는 온프레미스 NFS over TLS 지원을 추가합니다. 또한 이 릴리스에서는 LIF별 선택적 상호 TLS 호스트 인증과 일치하는 클라이언트에 대한 비 TLS TCP 액세스를 거부하는 내보내기 정책 제어를 지원합니다. NFS over TLS는 기존 ONTAP NFS 인프라와 함께 작동하므로 애플리케이션은 TLS가 전송 중인 NFS 트래픽을 암호화하는 동안에도 NFS를 정상적으로 계속 사용할 수 있습니다. ONTAP 9.19.1의 클라우드 플랫폼에서는 NFS over TLS를 사용할 수 없습니다. 자세한 내용은 https://docs.netapp.com/us-en/ontap/nfs-admin/enable-nfs-over-tls-task.html["TLS를 통한 NFS 활성화"^]을 참조하십시오.
